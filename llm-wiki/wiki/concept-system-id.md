# Concept: system id

**Summary**: The UUID that identifies a container host. Same id is used across the SSH pool, the SQLite/PostgreSQL systems table, the Tauri state, the URL parameters, the WebSocket paths, and the agent's context. Central routing key.

**Sources**: `crates/containerus-core/src/models/system.rs`, `src/app/state/system.state.ts`.

**Last updated**: 2026-04-16

**Parent**: [[frontend-overview]]

## Shape

```rust
pub struct SystemId(pub String);   // UUID v4, string-encoded
```

Newtype wrapper around a string. Generated with `uuid::Uuid::new_v4().to_string()` in `AppState::add_system` when the caller didn't supply one.

## Where it's used

| Place | Role |
|---|---|
| `systems.id` (SQLite, Postgres) | Primary key |
| `AppState.systems` (desktop) | Keyed by id |
| `SshConnectionPool.connections` | `DashMap<system_id, SshClient>` |
| `ConnectionManager.shared` (server) | `DashMap<Uuid, _>` |
| `ConnectionManager.per_user` (server) | `DashMap<(user_id, system_id), _>` |
| `MonitoringManager.active_monitors` | `DashMap<system_id, _>` |
| `PortForwardManager.forwards[*].system_id` | Lookup |
| `BackendService._systemOwnership` | `Map<system_id, connection_id>` |
| URL params | `/terminal/:systemId`, `/files/:systemId`, … |
| WebSocket paths | `/api/ws/terminal/:systemId`, `/api/ws/tunnel/:systemId` |
| Tauri commands | almost every command takes `systemId` |

## Why a UUID and not a hostname

- Hostnames change. A server rename would orphan every reference.
- Two systems may share a hostname (different ports, different jump chains).
- UUIDs let the user rename freely without breaking saved references.

## Local vs backend

Local-mode systems have ids generated by the desktop app. Backend-mode systems have ids generated by the server and delivered to the client inside project/environment listings. Ids don't collide because UUID space is huge, but they also don't overlap semantically — two different systems can never have the same id across the union.

`BackendService._systemOwnership.get(id)` returns:
- `undefined` → local system → use Tauri
- `connectionId` → backend system → use HTTP against that connection

This is the sole routing rule of [[dual-path-routing]].

## Stable across restarts

Ids are persisted in the `systems` table. On relaunch, `AppState::new` rehydrates them. Any cached references in memory (SSH pool entries, metric handles) get rebuilt on first use.
